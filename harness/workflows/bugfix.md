# Bugfix Workflow

1. `develop`에서 `bugfix/OOO` 브랜치를 생성한다.
2. 재현 절차, 기대 결과, 실제 결과를 기록한다.
3. 로그와 관련 테스트로 원인을 좁힌다. 증상만 가리는 수정은 피한다.
4. 실패를 재현하는 테스트를 먼저 추가하거나 기존 테스트를 보강한다.
5. 최소 범위로 수정하고 API·트랜잭션·화면 계약의 회귀를 확인한다.
6. `./scripts/verify.sh`와 버그 재현 테스트를 실행한다.
7. 수정 원인, 영향 범위, 검증 결과를 리뷰에 남긴다.
8. 확인된 수정만 리뷰를 거쳐 `develop`에 수동으로 병합한다.
