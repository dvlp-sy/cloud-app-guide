# Review Checklist

## 기능과 도메인

- [ ] 요구사항과 변경 범위가 일치하는가?
- [ ] 상품 등록 시 상품과 재고가 함께 생성되는가?
- [ ] 잘못된 수량·상품·회원 입력이 거부되는가?
- [ ] 주문 시 재고가 충분한지 확인하고 차감하는가?
- [ ] 주문 취소는 `ORDERED` 상태에서만 가능하고 재고를 복원하는가?
- [ ] 주문 금액과 `priceSnapshot` 의미가 보존되는가?

## API와 백엔드

- [ ] Controller가 업무 규칙을 직접 구현하지 않는가?
- [ ] Service의 트랜잭션 경계가 유지되는가?
- [ ] 생성자가 외부에 직접 노출되지 않고 정적 팩토리 메서드로 객체를 생성하는가?
- [ ] 특별한 이유 없이 변경 가능한 필드나 setter를 추가하지 않았는가?
- [ ] 스프링 빈이 요청별 데이터나 공유 가변 상태를 필드에 보관하지 않는가?
- [ ] Service와 Repository의 Query·Command 책임이 분리되어 있는가?
- [ ] JPA Entity가 API 응답으로 직접 노출되지 않는가?
- [ ] `ApiResponse<T>` 형식과 성공 코드가 일관적인가?
- [ ] API 문서 interface와 프론트 호출부가 함께 갱신되었는가?

## 프론트엔드

- [ ] 공통 레이아웃은 `layout.html`과 `style.css`를 재사용하는가?
- [ ] 도메인 전용 HTML·CSS·JS가 해당 도메인 디렉터리에 있는가?
- [ ] 공통 CSS에 도메인 전용 선택자를 추가하지 않았는가?
- [ ] `fetch`가 HTTP 상태와 `isSuccess`를 모두 처리하는가?
- [ ] 기존 화면의 레이아웃과 반응형 동작이 유지되는가?

## 안전성과 검증

- [ ] 비밀번호·토큰·DB 자격 증명이 diff에 없는가?
- [ ] 무관한 파일이나 생성물이 포함되지 않았는가?
- [ ] `git diff --check`가 통과하는가?
- [ ] `./scripts/verify.sh`와 필요한 추가 테스트를 실행했는가?
