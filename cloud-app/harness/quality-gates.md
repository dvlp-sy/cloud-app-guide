# 품질 게이트

## 필수 게이트

모든 변경은 다음을 통과해야 한다.

1. `git diff --check`
2. `./gradlew test`
3. 저장소 구조와 공백 오류 검증을 포함한 `./scripts/verify.sh`

`main`에 반영하거나 배포하기 전에는 리뷰어가 품질 게이트 결과를 직접 확인해야 한다. CI는 검증만 수행하며 자동 승인·자동 병합을 수행하지 않는다.

## 릴리스 게이트

- [ ] 변경이 `develop`에서 통합·검증되었는가?
- [ ] 변경이 리뷰어 확인 후 수동으로 `main`에 반영되었는가?
- [ ] 배포 태그가 `vMAJOR.MINOR.PATCH` 형식의 유효한 Semantic Versioning인가?
- [ ] 커밋 메시지가 변경 종류에 맞는 Conventional Commits 형식인가?
- [ ] 변경 내용이 해당 버전의 릴리스 범위와 일치하는가?
- [ ] CD가 자동 병합 없이 테스트와 패키징만 수행하는 것을 확인했는가?

## 변경 유형별 추가 게이트

### 백엔드

- 도메인 규칙에 대한 단위 또는 통합 테스트
- API 응답 envelope와 HTTP 상태 코드 확인
- 트랜잭션 안에서 재고 차감·복원이 일어나는지 확인

### 프론트엔드

- 페이지가 `style.css`와 공통 layout fragment를 사용하는지 확인
- 도메인 전용 HTML·CSS·JS가 해당 도메인 디렉터리에 있는지 확인
- API 호출이 HTTP 상태와 `isSuccess`를 처리하는지 확인

### 설정·스키마

- 환경 변수 이름과 배포·로컬 프로파일의 의도를 보존
- 파괴적인 마이그레이션이나 자격 증명 노출 금지

## 알려진 제한

현재 테스트 스위트는 Spring context smoke test 중심이다. 따라서 테스트가 통과해도 모든 주문·재고 시나리오가 검증되는 것은 아니며, 기능을 추가할 때 해당 규칙에 대한 테스트를 함께 추가해야 한다.
